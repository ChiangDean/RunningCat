# 十七、美術素材精簡製作規格

最後更新：2026-04-11

## 1. 文件目的

本文件提供《喵喵衝撞派對》角色圖片、動畫圖片、背景圖與 UI 疊圖安全區的精簡製作規格。

用途有兩種：

- 提供 AI 生成圖片時的明確規格依據
- 提供繪師、像素動畫師、整合人員使用同一套尺寸與構圖標準

本文件不描述個別貓咪設定，只定義共通方向與交付規格。  
個別世界觀、美術氣質與風格方向，仍以 [13_image_art_direction.md](13_image_art_direction.md) 為最高優先。

---

## 2. 基準畫面

### 2.1 遊戲基準解析度

- 遊戲主要顯示基準：`720 x 1280`
- 螢幕方向：`直式`
- 主要裝置：`手機`

所有圖片與動畫在設計時，都必須先以 `720 x 1280` 的可視範圍思考，再放大輸出。

### 2.2 建議製作倍率

為了兼顧 AI 生成、裁切彈性與後續縮放，建議素材採以下倍率：

- 戰鬥角色動畫原稿：以遊戲內顯示尺寸的 `2x` 或 `4x` 製作
- 角色靜態圖：至少 `1024 px` 高
- 直式背景圖：優先 `1440 x 2560`
- 主視覺或活動圖：可用 `1536 x 2304` 或近似直式比例

若 AI 生成圖片，建議先生成較大尺寸，再縮小至遊戲需求，不要反過來放大。

### 2.3 基礎像素單位

建議所有像素風素材統一使用 `8 px` 作為基礎單位。

- 小間距：`8 px`
- 常用間距：`16 px`
- 大間距：`24 px`
- 區塊間距：`32 px`

若需要更細的內部修飾，可用 `4 px`，但主要版面與輪廓仍以 `8 px` 網格對齊。

## 3. 共通製作原則

### 3.1 角色比例原則

- 角色為擬人化雙腳站立貓咪
- 讀感應優先接近「小隊成員」而不是「Q 版貼圖」
- 輪廓要一眼可辨識，不可過細碎
- 優先側面或 3/4 側面，方便表現往前衝與碰撞

### 3.2 方向原則

- 我方主要朝右
- 敵方主要朝左
- 若使用同一張圖翻轉，需確保翻轉後不會出現文字、左右不對稱裝備、單側特殊標誌錯誤

### 3.3 AI 生成原則

若由 AI 製作，輸入需求至少應包含：

- 圖片用途
- 輸出尺寸
- 是否透明背景
- 是否需要保留 UI 安全區
- 角色數量
- 角色在畫面中的相對大小
- 構圖區域限制
- 禁止文字、浮水印、UI 框、Logo

## 4. 素材分類與交付規格

## 4.1 戰鬥角色動畫圖

### 用途

- 戰鬥畫面角色演出
- 戰鬥事件播放
- 技能發動與死亡演出

### 建議交付格式

- 檔案格式：`PNG`
- 背景：`透明`
- 每個動作一組 sprite sheet 或逐幀圖
- 命名格式：`cat_common_<action>_<dir>`

範例：

- `cat_common_idle_right.png`
- `cat_common_run_right.png`
- `cat_common_hit_right.png`

### 建議基準尺寸

- 單一角色遊戲內站立高度：`96 ~ 128 px`
- 單幀畫布建議：`160 x 160`
- 若是較寬的碰撞或翻滾動作，可用：`192 x 160` 或 `192 x 192`

### 建議最小動作清單

- `idle`
- `run`
- `collide`
- `knockback`
- `stagger`
- `wall_bounce`
- `skill`
- `death_fly`

### 建議幀數

- 待機：`4 ~ 6 幀`
- 跑步：`6 ~ 8 幀`
- 碰撞：`3 ~ 5 幀`
- 被擊退：`3 ~ 4 幀`
- 硬直：`2 ~ 3 幀`
- 撞牆：`3 ~ 4 幀`
- 技能：`4 ~ 8 幀`
- 死亡彈飛：`4 ~ 6 幀`

### 節奏建議

- 待機循環要輕，不要過度抖動
- 跑步重心要明確往前
- 碰撞瞬間要有「胸口或肩膀往前頂」的感覺
- 被擊退與撞牆要能明顯區分
- 死亡彈飛要保留空中翻滾或失衡感

### 輪廓安全要求

- 角色主輪廓至少保留 `2 ~ 3 px` 清楚外輪廓
- 四肢不可細到縮小後消失
- 耳朵、尾巴、頭身比例必須在縮小後仍能辨識是貓

---

## 4.2 角色靜態圖

### 用途

- 配置畫面角色圖示
- 強化頁角色卡面
- 技能說明或角色資訊面板
- 商店、活動、圖鑑延伸用圖

### A. 小圖示 Icon

- 用途：隊伍格、列表、按鈕縮圖
- 建議尺寸：`128 x 128`
- 安全內容區：`96 x 96`
- 四周保留：至少 `16 px`
- 背景：透明
- 構圖：頭部與上半身優先，不要塞滿整格

### B. 中型半身圖

- 用途：角色資訊、技能說明、彈窗
- 建議尺寸：`512 x 512`
- 安全內容區：`400 x 400`
- 角色主體建議占畫面：`65% ~ 75%`

### C. 全身展示圖

- 用途：強化頁、角色詳情、宣傳拼圖
- 建議尺寸：`768 x 1024`
- 背景：透明
- 角色腳底到畫面底部保留：`48 ~ 72 px`
- 頭頂保留：`48 px` 以上

### D. 技能 Icon

- 用途：戰鬥技能列、技能面板
- 建議尺寸：`128 x 128`
- 主圖形安全區：`96 x 96`
- 不可塞滿四角
- 不應依賴細字說明來辨識

---

## 4.3 直式背景圖

### 用途

- 首頁主背景
- 活動主圖
- 商店背景
- 養成頁背景
- 抽卡頁背景

### 建議輸出尺寸

- 主輸出：`1440 x 2560`
- 備用輸出：`1024 x 1820` 以上皆可

### 構圖分區

以 `720 x 1280` 基準畫面對應：

- 上方安全區：`y = 0 ~ 220`
- 中央主視覺區：`y = 220 ~ 760`
- 下方互動區：`y = 760 ~ 1160`
- 底部導覽保留區：`y = 1160 ~ 1280`

### 留白規則

- 上方需保留標題與資訊空間，不可放過於強烈的主體臉部
- 中段才是主要故事焦點
- 下方可有角色動勢，但不能影響按鈕辨識
- 最底部 `120 px` 高度應避免重要主體

### 左右邊界規則

- 左右邊各保留至少 `24 px` 安全邊
- 重要角色的頭、手、尾巴不要貼邊
- 若有群像，主體群建議集中在畫面寬度 `20% ~ 80%` 區域內

### 背景主體比例

- 單一大主體不應超過畫面高度的 `45%`
- 多角色群像總占比建議控制在畫面高度的 `25% ~ 40%`
- 背景細節應服務角色，不可搶戲

---

## 4.4 戰鬥背景圖

### 用途

- 主戰鬥畫面
- 競技場戰鬥畫面

### 建議輸出尺寸

- `1440 x 2560`

### 戰鬥區可視原則

參考目前主畫面結構，戰鬥與 UI 疊圖需保留以下區域：

- 頂部資訊區：`y = 0 ~ 120`
- 關卡/標題區：`y = 260 ~ 380`
- 戰鬥角色活動區：`y = 420 ~ 860`
- 技能列區：`y = 760 ~ 860`
- 底部導覽列：`y = 1170 ~ 1280`

### 戰鬥背景設計要求

- 中央水平碰撞帶要清楚
- 角色站位區後方不可有過多高對比物件
- 左右牆面或邊界元素可以存在，但不要過亮
- 角色主要碰撞線附近應保持相對乾淨

### 視覺優先順序

- 第一優先：角色可讀性
- 第二優先：碰撞與位移清楚
- 第三優先：居家場景氣氛

## 5. UI 疊圖安全區規格

以下規格是給背景圖、主視覺圖、活動圖使用的避讓準則。

## 5.1 首頁或主畫面安全區

以 `720 x 1280` 為基準：

- 左上按鈕區：`x = 20 ~ 240`, `y = 20 ~ 70`
- 中上計時/標題區：`x = 240 ~ 480`, `y = 20 ~ 80`
- 右上按鈕區：`x = 620 ~ 700`, `y = 20 ~ 70`
- 中央關卡/提示區：`x = 180 ~ 540`, `y = 260 ~ 380`
- 技能列區：`x = 90 ~ 630`, `y = 760 ~ 860`
- 底部導覽列區：`x = 0 ~ 720`, `y = 1170 ~ 1280`

以上區域不可放需要玩家辨識的主要角色頭部、臉部、重要道具、關鍵敘事點。

## 5.2 角色動態避讓規則

- 角色主要視覺焦點建議放在 `x = 120 ~ 600`
- 角色主要視覺焦點建議放在 `y = 360 ~ 820`
- 若為首頁群像，建議角色腳部活動區落在 `y = 700 ~ 980`
- 若為標題背景，角色臉部不應與頂部 UI 重疊

## 6. 間距與版面紀錄標準

未來若新增頁面圖片需求，至少應記錄以下欄位：

- 圖片名稱
- 圖片用途
- 是否透明背景
- 目標解析度
- 遊戲內顯示位置
- 遊戲內預估顯示尺寸
- 需要避讓的 UI 區域
- 主體建議占比
- 主體位置
- 是否可翻轉
- 是否允許裁切
- 是否需預留文字區
- 是否可用 AI 直接生成
- 後續是否需切圖或拆幀

建議統一用以下格式描述：

```text
Asset name:
Use case:
Canvas size:
Transparent background:
In-game placement:
Expected visible size:
Safe area:
Subject size ratio:
Subject position:
Cropping allowed:
Flip allowed:
Notes:
```

## 7. AI 圖片需求最小模板

若未來交由 AI 製作，建議每次至少提供以下資訊：

```text
Asset type:
Use case:
Canvas size:
Background:
Subject count:
Subject framing:
Subject size ratio:
Safe area to preserve:
Style direction:
Environment:
Lighting:
Palette:
Avoid:
Output notes:
```

### 範例

```text
Asset type: battle background illustration
Use case: main battle screen
Canvas size: 1440 x 2560
Background: opaque
Subject count: 0 to 3 background cats only
Subject framing: keep the center collision lane readable
Subject size ratio: no single subject above 20 percent of image height
Safe area to preserve: top UI area, middle collision lane, bottom skill bar and nav area
Style direction: cozy domestic pixel-art scene, readable game background
Environment: living room with wood floor, rug, curtain, cardboard box
Lighting: warm indoor daylight
Palette: natural home colors, low saturation warm tones
Avoid: logo, text, watermark, neon, candy palette, sci-fi, horror
Output notes: do not place important subjects in bottom navigation area
```

---

## 8. 禁止事項

- 不要把角色或主體貼齊畫面邊界
- 不要讓重要臉部落在 UI 疊圖區正下方
- 不要讓背景中心過於花亂，影響戰鬥可讀性
- 不要做成宣傳海報式滿版角色特寫
- 不要把像素風做成極細碎高頻噪點
- 不要在素材中直接寫文字、按鈕、Logo、浮水印
